# 第一輪試用與迭代方法

目標是找出使用者真正卡住與真正需要的地方。先做小型觀察，不先上複雜分析平台。主持人記錄不依賴產品內的事件收集，使用者可以全程不開啟回饋記錄。

## 1. 找誰、怎麼測

邀請 5–8 位未熟悉地占的使用者，至少覆蓋 iPhone、Android、電腦三種環境。另邀 1–2 位有實際地占經驗者，專門檢查術語、盤位與解讀範圍。不要把專家審校分數和新手易用性混在一起。

每人約 20–30 分鐘，可用虛構情境，不必提供私人問題。先觀察自然操作，再提問。卡住時先問「你以為下一步會發生什麼」，不要立即教他按哪裡。

### 主持人任務腳本

1. 「請用這個 App 思考一件一般的工作或生活情境，完成一次點沙起卦。」記錄需不需要協助、停在哪一列。
2. 「請指出結果裡一項你看得懂的內容，找到它的依據。」觀察是否能把文字與盤位連上。
3. 「請寫下一個可回顧的想法，離開結果頁後再找回來。」檢查日誌與筆記的預期是否一致。
4. 「請試試快速模式，再告訴我與點沙相比，你何時會想用哪一個。」測操作時間與儀式感取捨。
5. 「如果下週再打開，你最想回來看什麼？」記錄未提示的需求，再展示功能候選。

不要先展示所有未來功能讓受試者勾選「都想要」。先聽實際任務與遇到的困難。

## 2. 記錄表

| 欄位 | 例子 |
|---|---|
| 受試代碼、裝置、日期 | U03、iPhone、日期 |
| 完成情況 | 自行完成／提示一次／需代操作／未完成 |
| 卡點與原話 | 第 4 列找不到完成按鈕；「我以為按越久越有效」 |
| 第一次卡點所在步驟 | 提問／選宮／點沙第 N 列／結果／日誌 |
| 看懂依據 | 能自行指出／提示後能／不能 |
| 1–5 評分 | 操作自然、解讀易懂、願意回顧 |
| 主要想改一件事 | 自由文字，可不填 |
| 實際下一步 | 回到日誌／重抽／離開；不推論動機 |
| 專家額外欄位 | 規則問題、文案問題、流派差異、建議來源 |

先檢查至少 80% 可自行完成，以及至少 4/5 能指出一項依據。未達先修介面或說明，不急著增加 AI 長文。樣本小，應保留原話與具體行為，百分比只作內部門檻。

## 3. App 內回饋

結果下方可放「這次體驗如何？」三題：操作是否順手（1–5）、解讀是否容易理解（1–5）、最想改善的一件事（選填，最多 500 字）。評分不是占卜準確率。

設定中的「記錄本機試用流程」預設關閉。開啟後只留以下事件，再讓使用者手動匯出；不自動寄送或上傳。

```ts
type PilotEvent = {
  schemaVersion: 1;
  sessionId: string; // 本次流程的隨機 ID，不是帳號或裝置指紋
  name: 'session_started' | 'method_chosen' | 'row_confirmed'
      | 'chart_completed' | 'evidence_opened' | 'note_saved'
      | 'session_left' | 'error_shown';
  elapsedMs: number;
  method?: 'dots' | 'quick' | 'manual';
  rowIndex?: number; // 1–16，只記進度，不記點數
  errorCode?: string; // 白名單錯誤碼，不是 stack/state
};
```

不記 question、筆記文字、原始點數、母象、盤面、recordId、按壓座標或完整裝置指紋。sessionId 每次流程重建；不使用廣告 ID。最多保存最近 5000 事件，先移除最舊者，畫面提供全部清除。回饋文字只隨使用者明確匯出的 feedback 檔離開裝置，匯出前提醒不要填私密內容。

記錄 elapsedMs 時扣除背景停留較佳；做不到先記原始 elapsed 並註明，不拿跨日暫停當操作耗時。不能保證關閉分頁一定收到 session_left；缺少完成事件只列為「觀察未完成」，不要直接認定使用者不滿。

## 4. 如何決定下一輪

先按影響排序，再看出現頻率，最後看修復成本：

| 層級 | 例子 | 處理 |
|---|---|---|
| A 立即修 | 錯盤、點擊雙算、結果重抽、資料消失 | 停用有問題路徑或先修，再測 |
| B 優先修 | 多人找不到下一步、看不懂依據、誤選宮位 | 改流程／說明，重做同任務 |
| C 小型比較 | 點沙太久、希望長按、動畫拖慢 | 做局部原型，與既有方案比較 |
| D 收入待辦 | 登入、AI、更多流派、分享社群 | 確認具體使用情境後再估 |

若多人中途放棄 16 列，先比較簡化提示、逐母節奏、快速入口可見度；再測四次長按。長按若引入，是新的數位取樣介面，須寫清楚來源，不可只換動畫卻說是手動點數。

若多人認為解讀太籠統，先確認他們是需要更好的問題分類、易懂證據，還是完整成就技法。前兩項可用現有內容改善；第三項才需要專家規則擴充。AI 文案不是缺少判讀規則的替代品。

```text
對運算、資料、內容版本的影響：

```

每輪只選少數可驗證的改動。保留版本與觀察，讓「改善體驗」變成可以對照的工作，而不是一直換外觀。
